Day 1 费曼卡(睡前全部过一遍)

向本科生解释:policy gradient 为什么成立?log-derivative trick 那一步在干嘛?
对照要点
∇E[R] 不能直接算因为期望依赖 θ;∇π = π·∇logπ 把梯度塞进期望内部,变成"可采样"的形式:E[R·∇logπ]。直觉:好轨迹的概率被推高,坏的被压低,R 是推力大小。高方差三源:轨迹长、reward 稀疏、没有对比基准。
为什么减掉 baseline 不引入偏差?GRPO 的 baseline 和 PPO 的有什么本质区别?
对照要点
E[b·∇logπ] = b·∇∫π = b·∇1 = 0(b 不依赖动作)。PPO 的 baseline 是训练出来的 value model(要多养一个网络);GRPO 的 baseline 是同 prompt 采 G 条的组均值——免训练,代价是每步要多次采样、且组内同质时会失效(零梯度陷阱)。
三句话讲清 0.5B GRPO collapse 的机制(带数字)。
对照要点
① 0.5B 太弱,gate 类样本组内 8 条采样全违规的比例高达 55%(1.5B 是 0%),组内 reward 全相等 → advantage≈0 → gate 行为拿不到任何梯度。② 非 gate 行为持续被强化,gate 动作份额从 62.6% 灭绝到 1.9%,KL 冲到 5.07(健康 run 0.36)。③ 后续 full-parameter GRPO 不崩,所以重归因为 LoRA adapter 容量地板,不是模型能力地板——温度探针(T=1.0 时 gate 仅 0.25)证明是真知识丢失而非解码伪影。
五次自我修正,按时间顺序,每个一句话+一个数字。
对照要点
① 多 seed:1.5B"胜过 prompted 7B"在 3-seed 均值下不成立 → 降级结论。② 0.5B collapse 重归因:full-param 不崩 → adapter 容量地板。③ 7B full-SFT 低分是 lr 伪影:2e-4→2e-5 后 0.5079→0.8473。④ AMD_00 裁决:证据显示该样本应为 smart-review 层,test gate 分母 8→7(改考卷要走仲裁,不是改模型)。⑤ v0.3 饱和:7+ 配置全命中 oracle 0.8473 → 停止刷方法,升级 v0.4 记忆考卷。

Day 2 费曼卡

DPO 推导链讲给同事听:为什么"不训 reward model 也在隐式地用 reward"?logZ 为什么消掉?
对照要点
KL 约束下 RLHF 目标有解析最优解 π*∝π_ref·exp(r/β)。反解出 r = β·log(π*/π_ref) + β·logZ(x)。代入 Bradley-Terry 的 P(y_w≻y_l)=σ(r_w−r_l) 时,两个 r 共享同一个 x,logZ(x) 相减抵消 → loss 只含四条 logp。所以 DPO = 把"最优策略的隐式 reward"直接塞进偏好分类损失;β 越大离 ref 越近。
你的 DPO 为什么输给 SFT?为什么说是"结构性保守"而不是没调好?
对照要点
1.5B DPO:gate 1.000 / success 0.58——完美安全但探索贫乏。证据链:pair v2 重构 + β∈{0.1,0.3,0.5} 全扫,β=0.3/0.5 恢复部分探索但仍低于 SFT(0.7495)。结论:偏好目标≠任务 reward,pair 里"更安全"的一侧系统性地被 chosen,把策略推向保守;这是目标错配,不是单点超参事故。这是"偏好目标和任务目标可能不一致"的一手负面证据。
KV cache 为什么能加速?它的显存代价怎么算?
对照要点
自回归第 t 步只有 1 个新 query,历史 K/V 不变——缓存后每步从 O(t²) 降到 O(t)。显存:2(K和V) × layers × kv_heads × head_dim × seq_len × dtype字节 × batch。例:7B(32层, GQA 8 kv头×128维)fp16、4k 上下文、batch 1 ≈ 2×32×8×128×4096×2B ≈ 0.5GB;batch 32 就是 16GB——这就是为什么推理服务的瓶颈是 KV cache,也是 PagedAttention 存在的理由。

A · 训练与推理系统(字节 infra 面必问)

1. 显存估算(几乎 100% 会问)

为什么问:5 分钟检验你是否真训过模型。

骨架:全参 Adam 混精 16 字节/参(2+2+4+4+4);7B→112GB;LoRA 把梯度+优化器压到 adapter 规模;激活显存靠 gradient checkpointing 换;推理 = fp16 权重 + KV cache(公式见 Day 2 费曼卡)。你的独家素材:80GB 单卡跑 7B full-FT 用了 bnb 8bit optimizer——讲实操细节。

2. DDP / ZeRO-1/2/3 / FSDP / TP / PP

为什么问:千卡集群的入场券词汇。

骨架:DDP 每卡全量+allreduce 梯度;ZeRO 依次切 optimizer states→梯度→参数;FSDP≈ZeRO-3;TP 切层内矩阵(机内 NVLink);PP 切层间(气泡);实际 = 3D 并行组合。诚实说单卡出身,然后把话题引到"RL 训练的特殊显存压力:policy+ref 同驻"。

3. 推理优化:vLLM / PagedAttention / continuous batching / 投机解码

为什么问:post-training 岗常兼推理部署;GRPO rollout 本身就是推理负载。

骨架:KV cache 是瓶颈 → PagedAttention 把 cache 分页消灭碎片;continuous batching 按 token 级调度不等最慢请求;投机解码 = 小模型草稿+大模型并行验证。连接:GRPO 每 prompt 采 G=8 条,rollout 吞吐直接决定训练速度。

4. 异步 RL / rollout-learner 分离

为什么问:2026 大厂 RL infra 的标准形态。

骨架:rollout worker(推理引擎)与 learner(训练)分离 → 权重同步有延迟 → 样本 stale → off-policy 修正靠 importance ratio(PPO 的 ratio 本来就是干这个的)。可引用 minimind 的 SGLangRolloutEngine 是极简版。

5. 训练稳定性急救包

为什么问:"训练 loss 炸了你怎么办"是经典压力题。

骨架:查序列:数据(脏样本/超长)→ lr(warmup 够不够)→ grad norm(clip 阈值)→ 精度(bf16 优于 fp16,fp16 要 loss scaling)→ 恢复:回滚 checkpoint + skip batch。你的素材:7B lr 2e-4 伪影就是 lr 敏感性的一手案例;KL 5.07 是 RL 版的"炸"。

B · 算法盲区(算法面追问链的下一环)

6. DPO 变体一句话:IPO / KTO / SimPO / ORPO

为什么问:你简历写了 DPO,追问变体是自然延伸。

IPO:把 sigmoid 换成平方损失,防 DPO 对确定性偏好的过拟合;KTO:不要成对数据,只要单条 好/坏 标签(前景理论);SimPO:去掉 ref model,用长度归一化的平均 logp 当隐式 reward;ORPO:把偏好项并进 SFT 一阶段完成。你的连接:我们的 DPO 保守化问题,SimPO 的长度归一化也救不了——因为错配在偏好数据本身。

7. Reward hacking / Goodhart / 长度偏置

为什么问:RLHF 的核心痛点,Anthropic 尤其爱问。

骨架:代理指标被过度优化就与真实目标脱钩;经典症状:长度膨胀、格式套话、谄媚。防线:KL 锚、reward model ensemble、held-out 人评、过程监督。你的素材:citation 的"抄 ID 得分"就是微型 reward hacking,解法是改 action space 而非加惩罚——设计掉漏洞比对抗漏洞便宜。

8. Process RM vs Outcome RM / RLVR / 长 CoT RL(o1/R1 路线)

为什么问:2026 后训练的最热主线;你用 GRPO,R1 也用 GRPO,必被联想。

骨架:ORM 只看结果,PRM 给每步打分(贵但抗 hacking);RLVR = 可验证奖励(数学/代码/规则)绕开 RM 不可靠性——你的 escalation env 就是 RLVR 思路的 agent 版;R1 证明纯 RL 能涌现反思,但依赖强 base 模型——与你"0.5B 撞地板"的发现同构,可以打包讲。

9. on-policy vs off-policy;PPO 为什么是"近似 on-policy"

为什么问:RL 基本功分界题。

骨架:PG 理论要求样本来自当前策略;PPO 用 ratio+clip 允许旧样本小幅复用(一批数据训几个 epoch);太 stale 就失效 → 这正是异步 RL 的核心张力。DPO 是完全 off-policy(数据集是死的),这也是它便宜和它错配的共同来源。

10. Scaling laws / Chinchilla / MoE 一段话

为什么问:通识雷达,考你是否关注训练全局。

骨架:Chinchilla:算力最优时参数与数据应同比扩(~20 token/参数);推理成本约束下实际都过训(小模型多喂)。MoE:FFN 换成 top-k 路由的专家组,参数↑算力不变,代价是负载均衡(aux loss)与显存;minimind 里有极简实现可引用。

11. Tokenizer / BPE

为什么问:偶发手撕题("讲讲 BPE 怎么训练")。

骨架:从字节/字符起步,迭代合并最高频相邻对直到词表满;LLM 用 byte-level BPE 保证无 OOV。知道 minimind 用 6400 词表自训过即可,不必深挖。

公式一屏(白板热身用)

PG:        ∇J = E_τ[ Σ_t ∇log π(a_t|s_t) · Ĝ_t ]          (log-derivative trick)
Baseline:  E[b·∇log π] = b·∇∫π = 0                        (无偏,降方差)
PPO:       L = E[ min(r·A, clip(r,1±ε)·A) ],  r = π/π_old
GRPO:      A_i = (R_i − mean(R_group)) / (std(R_group)+ε)  (组均值=免训练 baseline)
DPO:       L = −log σ( β[(logπ_w−logπref_w) − (logπ_l−logπref_l)] )
GAE:       A_t = Σ (γλ)^k δ_{t+k},  δ_t = r_t + γV(s_{t+1}) − V(s_t)
KL(k3):    E[ exp(Δ) − 1 − Δ ],  Δ = logπ_ref − logπ_θ    (非负,低方差)
显存:      全参Adam混精 ≈ 16 B/param;KV cache = 2·L·H_kv·d_h·T·2B·batch
