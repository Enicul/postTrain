## 〇 · 一句话定位
我在一家做金融的创业公司做技术。我的项目是给一个理财 copilot 训练**本地决策模型**——
但它的起点是一个真实的产品失败,终点是一套判断"**训练到底值不值**"的方法。

## 一 · 起点:我们先撞了一次墙
最开始我们想做的是**用 AI 自主找 alpha、自动做量化**。做下来发现一个判断:对一个小团队,
可持续的优势**不在生成策略**——生成策略太便宜了,而且一个拟合了回测的策略,和曲线过拟合
的噪声其实分不开,你生成上千个总有几个碰巧好看的;市场又是非平稳、有反身性的,边缘一旦被
行动就衰减。**优势在验证策略,而验证需要人的判断。** 所以我们转向了**人在环路的 copilot**:
让人来做决策,让 AI 去做它真正擅长的——蒸馏知识、递送信息。这个转向其实很自然,因为我们
探索自动化的那段时间,一直在做的事本质上就是**把我们自己和一些专家的领域知识蒸馏出来**。
既然真正在积累的是知识和信息优势,那就把它打包教给用户。
> 若被追问"为什么不直接用大模型 API 调度":延迟和成本——本地小模型每次调用都要付费,
> 这正是我要验证"训练到底值不值"的原因。

## 二 · 产品,和我负责的那块
中间还有一步:AI 量化吸收太多噪音、当时的模型没能力做所有决定,所以我们先想的是——
**把专家在关键节点的决策提取出来,教给 AI,能不能提升它**(这条线同事在做)。做着做着
意识到,这套专家决策知识本身就是我们**最强的壁垒**——那就把它打包成服务给用户。
这就是 KIWI:领域知识 + 我们的新闻信息 + 回测系统,一个理财研究 copilot。

**我负责的是记忆这一层,具体是两个核心问题**:
1. **知识的管理与递送时机**——专家知识怎么组织、在合适的时间给到用户,而不是一股脑倒
   (这条后来长成了 digest/信息递送层);
2. **用户记忆的长期存储与更新**——最有代表性的困惑:用户说"我要梭哈",我们是照做?
   说教?还是**调取专家知识供他自己决策**?更深一层:该不该**记住这个用户容易梭哈**,
   从而长期调整引导方式、不总给偏激意见。
   **这个例子后来成了 v0.4 孪生对的产品原型:同一句话,用户记忆不同,正确行为翻转。**

现在有**一千多个注册用户、80 到 90 个在活跃使用**,包括我们自己——我们是自己的
第一批用户,先解决我们自己真实的研究痛点。

## 三 · 问题浮现:为什么会走到"训练"这一步

**先讲产品架构的三代演进(训练的动机藏在这里):**
- **v1 · workflow 式**:硬性规定直接写进 prompt,配**传统 NLP 的关键词/规则路由检索**
  (当时没上向量检索)。问题:**呆、慢**——用户问一句"今天股价多少"也要走全流程等半天。
- **v2 · 意图识别**:预设了部分意图类型做路由。灵活了,但引入不确定性:用户的可能性
  穷举不完;**尤其是载入了用户记忆和预设的专家记忆之后,路由明显更不准**。标志性事故:
  有一次 LLM 长时间不回复,查下来是**读了太多文件、上下文塞爆罢工**。
- **v3 · 分层**:核心问题变成——**什么该训进权重、什么放 prompt、什么写死 guardrails**;
  而且这种高频分流每次调 API 太贵。于是开始打点收集数据,走向后训练。当时的想法是三条:
  1. 高频、结构化、可验证的决策(路由/意图/熔断)→ 训进本地小模型:便宜、快、稳定可复现;
  2. 低频、开放式的深度任务 → 留给 frontier API;
  3. 绝对不能错的红线 → 不交给任何概率模型,写死在代码 guardrails;prompt 是最便宜的
     引导层,随时可调。
  **三重保障就是这个分层的执行,训练是任务阶梯的最后一级。**

同时,我们发现 **agent 的决策不稳定**——它会幻觉、会乱说、会在关键的地方乱做决定,
说实话让我们有点恐慌。因为这是个**涉及钱的金融产品**,一个乱决定是要赔钱的,我们要给
用户最大的安全感。prompt 保证不了输出绝对稳定。具体是四类事故:第一,给结论的时候**引用不存在的来源**——长 ID 场景下 prompted 的**伪造率
是 0.871**;第二,最让我们紧张的,用户说"我用 2 倍杠杆 SOXL 当对冲",agent **用自己的
判断替用户背书**("这对冲思路不错")、顺着聊下去,而不是把这个红线风险**升级给人工专家
复核**;第三,乱烧钱,同一个查询有时秒答、有时拉起一整条研究链,成本差一个量级;第四,
同一个结论的新闻**刷屏式轰炸用户**。所以我们的方案是**三重保障:代码层的硬红线 guardrails
+ prompt + 后训练模型**。

**关于"交给人"要说精确**:risk gate 是三档——**自动放行 → 智能复核(smart-review,
自动二次复核)→ 人工专家熔断**。"交给人"指的是**升级到人工专家/顾问那一档**(就是我们
当初蒸馏知识的那批专家),不是让用户自己拍脑袋。危险的不是"谁决定",是 agent 在红线动作
上**自作主张、把用户哄进一个危险操作**。熔断这种硬约束我们**留在代码层**,不赌 RL 能学会——
后面我用实验证明了这是对的。
> 若被追问"专家档谁来做、90 个用户撑得住吗":如实说规模与人力现状(early-stage),
> 别把它吹成一个成熟的 24/7 人工审核流水线。

## 四 · 方法:我把"失败"当成一个测量问题
我没有一上来就"我们跑个 GRPO"。我先把每一个目标行为写成一个**可验证奖励的环境**:
给定一个真实的 KIWI query,策略选一个首动作——便宜、深挖、还是熔断——然后按"最终正确性
减 λ 乘累计成本"打分,熔断漏判扣 2.0 的安全惩罚。然后我**先把判据划死**:训练要想算数,
得比 SFT 高至少 3 个点的 reward,**并且**熔断召回到 0.99——这条线是**事先注册**的,不是
事后凑的,所以数据说不值就是不值。在这之上我跑了一整个矩阵:SFT、DPO、GRPO 三种方法,
乘 0.5B 到 7B 四个尺寸,乘 LoRA 和全量微调两种参数化,每一次运行都留了 manifest,配置、
git 哈希、依赖版本全冻结,可复现。**而且我会停**:citation 这个任务,engineered prompt
已经过了 kill bar(frontier 到 0.957),我就没有去做 SFT/GRPO——不为训练而训练。
> 若被追问"环境是真的还是模拟":模拟,但便宜路成功率来自一张盲测集成的真实结果表,
> 不是拍脑袋编的,我在诚实边界里明确写了。

## 五 · 三个最硬的结果
第一,**3B 在 GRPO 上,三个种子全部精确命中解析最优 0.8473,标准差是零,熔断召回 100%**——
不是平均接近,是零方差压在理论天花板上。第二,也是我最想讲的:**0.5B 崩了**。我没当玄学放过,
做了零梯度机制诊断——GRPO 用组内相对优势,当一组采样在熔断题上**全部同样违规**时,组内优势
约等于零,那 2.0 的惩罚根本传不出梯度;我量化了它,**0.5B 的全违规率是 0.55,1.5B 是 0.00**,
这就是小的崩、大的不崩。而且我**翻案**了:换成全量微调,同一个 0.5B 不崩——所以这是
**adapter 容量下限,不是模型能力下限**。第三,**考卷被考爆了**:七个以上的配置精确命中同一个
最优值,顶端失去区分度。我没庆功,把它冻结成历史标尺,重建了一张更难的。这一路我一共
**主动推翻自己五次**:一个种子成立、平均不成立的头条我撤了;一整条"规模曲线"我查出来是
超参混淆、翻案重写了。

## 六 · 最新一章 + 这一切到底证明了什么
新考卷叫 v0.4,换了个轴考"**记忆利用**":用三个并行 agent 模拟出 36 个 KIWI 用户、长出
**592 道依赖记忆的"孪生"题**——同一个问题,记忆不同,正确答案就翻转,逼模型真的用上记忆。
**首考刚跑完(1.5B prompted 基线)**,两条干净的结论:一,**记忆需要训练**——把记忆摘要喂给它,
它几乎拿不到增益(digest 0.7022 对 none 0.7052),说明记忆利用这个行为不是 prompt 白给的,
得训进去,**训练臂是我的下一步**;二,**长上下文会淹死小模型**——原文 dump(1078 token)
信号最多,但 success 从 0.984 崩到 0.645,掉了 34 个点。这一条特别有意思,因为它**独立证明了
我们产品的设计**:KIWI 里我做的就是**给 agent 摘要而不是原文 dump**。所以整条线下来,
**真正值钱的不是某个漂亮数字,是那套纪律**——先划判据、让数据淘汰方法、每个负结果和正结果
一样如实记账、证据关闭一条路就停止烧 GPU。它不绑定任何尺寸或任务,能迁移到任何规模的后训练。
**产品和训练是一个闭环:产品负责发现失败,训练负责把失败变成可测可训的任务再回答它;
我在产品侧做的记忆系统,正是训练侧 v0.4 考的那个能力。**

**两条祖先线索(深挖时把故事缝成一张网的针脚):**
- 段二的"梭哈"困惑 = **孪生对的产品原型**——同一句话、用户记忆不同、正确行为翻转;
- 段三的"载入记忆后路由更不准"+"读文件罢工"= **v0.4 的任务定义与 raw 臂发现的产品祖先**——
  v0.3 考裸路由,v0.4 考带记忆的路由,恰好复刻产品从 v1 到 v2 撞的墙。
> 若被追问"那到底该不该上 RL":看任务——escalation 上 RL 买到 +4.9 个点的效率,
> citation 上一旦数据健康 RL 增量精确为零,所以"不为 RL 而 RL"是实测出来的,不是口号。
